# 雕版展会网页复用工作流

适用范围：沿用段和段律师事务所现有雕版网页，更新下一次展会的作品、双语故事及 iPad 自动循环展示。

- [正式网址](https://cyber60j.github.io/Chinese-woodblock-printing/)
- [项目仓库](https://github.com/cyber60J/Chinese-woodblock-printing)
- [2026 AIPPI 发布与故障复盘](exhibitions/2026-10-07-aippi.md)

## 1. 收集下一次展会资料

用户可以分批提供照片和故事，无须先准备完整文稿。每组作品记录：

| 项目 | 需要的信息 |
| --- | --- |
| 展会 | 名称、年份；日期、地点仅在页面需要显示时收集 |
| 作品 | 名称、雕版本体图、印刷效果图；一对作品说明对应关系 |
| 故事 | 寓意、题字、来源，以及希望向来宾传达的内容 |
| 参与 | 能否自行印制、滚轴或其他操作方式、是否仅供观赏 |
| 补充资料 | 作者、年代、原型、遗址等；没有依据时标为待确认 |
| 展示设备 | 实际使用的 iPad 与浏览器；验收时尽量记录型号及系统/浏览器版本 |

可直接发给下一次任务的说明：

> 沿用雕版展会网页工作流，为【展会名称与年份】更新页面。我会分组上传雕版图、印刷效果图和故事，并说明哪些作品可以上手印制。请沿用现有双语格式、大字体和自动循环展示；按我要求的顺序先展示文案或 demo，再更新正式网址。

## 2. 整理作品和双语文案

1. 按展会保存素材，例如 `assets/aippi-2026/`；保留上一届素材和原图，不修改照片库原件或项目外的同步参考文件。
2. 照片放入素材目录后，在 `tools/prepare_images.py` 中为每张照片量取四个角，运行脚本生成拉直裁切后的整图、网页图和缩略图；必要时用 `trim` 单独裁去残留的画框内壁。不修改 `-original.jpeg` 原图。分享预览图用 `tools/make_share_assets.py` 更新展会名称、展位号后重新生成。
3. 参考 `assets/aippi-2026/artworks.json` 逐组建立图片、名称、故事、资料来源和参与方式的对应关系；参考 `assets/aippi-2026/introduction.json` 保存总介绍。当前网页不会自动从这些 JSON 生成，修改文案时也须同步页面。新展会重新记录确认状态、参与依据和发布状态；旧 `approved_for_publication` 不代表新内容已经获批。
4. 先读印样题字，再核对人物和纹样身份。发生误认时保留更正依据，不能继续沿用错误名称。
5. 文化背景按需要查证，以博物馆、图书馆、联合国教科文组织等原始机构资料为优先来源。一般龙纹或印刷历史资料不能证明某一件雕版的具体年代、作者或原型。
6. 英文面向展会来宾，用易懂的短段落说明寓意；遇到谐音或双关，解释中文词义，避免仅逐字翻译。
7. 按用户指定顺序提交文案或 demo。已确认内容不反复要求确认；新增且影响真实性的信息应先核实。

缺图或缺故事时可先制作结构和文案草稿，用明确占位标注待补内容，说明哪些部分尚未核实；只有已确认是同一件作品时才复用旧图和具体题字描述。不能用上一届另一件作品补空，也不能把缺资料的 demo 视为作品内容已验收。

## 3. 沿用页面结构

基线为当前 `index.html`（旧 `ipad-display*.html` 已删除）。保留红色欢迎区、浅色背景、中文与英文对应介绍、作品卡片、完整图片链接、雕版本体展开区及清晰的参与标识。

- 欢迎区下方的作品缩略图、语言切换（中 / EN、中文、English）、拓印步骤和"关于段和段 / 联系我们"区块随展会更新：展位号、律所介绍、同事联系方式均以用户最新提供的为准。
- 语言切换依靠每段文字的 `lang="zh-CN"` 或 `lang="en"` 标记；新增文案时中英文分别放在带 `lang` 的元素里，标题中的分隔号用 `<span class="sep">`。作品中文名不加标记，在英文模式下保留。

- 更新展会名称、欢迎词、作品图片、双语介绍、展示顺序及来源。
- 重新核算组数、图案数和可自行印制数量。本次八组、七款是 2026 AIPPI 的数据，不是固定模板要求。
- 字号与排版默认沿用当前 iPad 版本：宽屏基础字号 20px，600px 以下 18px；按新内容检查换行和遮挡。
- 当前演示页为 `aippi-2026-demo.html`，现有测试默认读取此文件。新展会可另存相应 demo，并让其播放脚本与正式入口一致；新增或更名的 demo 都须纳入对应测试，不能因为保留了旧 demo 而漏验新页。
- 本地演示优先通过 HTTP 服务查看。展台最终验证使用正式 HTTPS 网址。

## 4. 保留自动循环的行为约定

| 操作或情况 | 预期行为 |
| --- | --- |
| 打开普通网址（访客手机） | 不显示控制条，不自动滚动 |
| 打开 `?display=1` 网址（展台 iPad） | 显示启动倒计时，约 4 秒后自动向下滚动；隐藏语言切换 |
| 点击暂停 | 立即停止，持续保持暂停，直到用户明确继续 |
| 点击继续 | 立即覆盖阅读等待及残留触摸状态，开始移动；在底部则回顶开始 |
| 手动滑动或阅读 | 暂停自动展示；手指松开后约 10 秒恢复，也可点继续立即恢复 |
| 触摸时指针被取消 | 手指仍在页面上时保持停止，不因指针取消提前恢复 |
| 转屏、工具栏高度变化 | 不重置阅读等待；慢速仍能累积小数像素前进 |
| 到达底部 | 停留约 4 秒，回到顶部，再等待约 4 秒开始下一轮 |
| 后台与返回 | 后台不滚动；返回时保留用户明确暂停状态，否则短暂倒计时后恢复 |
| 播放提示 | 与真实条件对应，区分播放、暂停、阅读等待、启动和本轮结束 |

实现约束：按钮只使用一次原生点击切换；自动滚动触发的 `scroll` 事件不能被误认成手动阅读；明确继续必须清理旧等待及触摸/指针记录。保留小数像素进度，不能每帧从取整后的 `scrollY` 重新开始。

## 5. 验证、发布和现场验收

修改播放逻辑后，运行已有回归检查，不为无关文案修改另写重复测试：

```sh
node --test tests/playback.test.cjs
```

当前 11 项检查覆盖正式页与 demo 的脚本一致性、普通网址不自动滚动、启动、立即继续、触摸残留、尺寸变化、持续暂停、自身滚动事件、指针取消、到底循环及图片高度增长。HTML、测试、工作流变化时，GitHub Actions 自动运行这些检查；该检查目前不会自动阻止独立的 GitHub Pages 发布流程。

发布时先核对本地修改和远端最新提交，保留现有改动。使用可用的 Git 凭据或 GitHub 连接器提交，只包含本次相关文件；通过连接器更新分支时核对预期旧提交，不强制覆盖远端。遵守本次任务已有发布授权，不把历史授权写成未来通用授权。

发布后确认部署成功、正式网址已返回新版内容，再检查普通浏览器与平板尺寸下的实际页面移动。不能以按钮文字变化、提交成功或本地 demo 正常替代线上验证。

展台实际 iPad 的最少检查清单：

- [ ] 打开并刷新 `?display=1` 网址，能看到本次展会、正确图片及播放状态。
- [ ] 用手机扫码打开普通网址，页面不自动滚动、没有控制条。
- [ ] 暂停至少 15 秒仍静止；暂停时转屏不会自行恢复。
- [ ] 点继续立即移动；刚手动滑动后点继续也立即移动。
- [ ] 手动滑动期间不与自动滚动争抢，松手约 10 秒后恢复。
- [ ] 横竖屏切换、工具栏收展以及慢速展示均能继续前进。
- [ ] 到底后正常回顶循环；展开雕版照片后新增内容也能展示。
- [ ] 中文、英文和控制条可读，页面末尾未被控制条遮挡。

分别记录自动检查、尺寸模拟和实际设备结果。不能直接控制现场设备时，如实记录限制；用户现场确认可以作为反馈，但不能扩展成所有检查项目均已实测。
